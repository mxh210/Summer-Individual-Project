## Overview

This project investigates the prediction of 30-day hospital readmission for patients with diabetes using the Diabetes 130-US Hospitals dataset.

The project first reproduces key parts of the study by Strack et al. (2014), including data preprocessing, descriptive analysis and logistic regression. It then extends the original study using modern machine learning models and evaluates their performance for 30-day readmission prediction.

The models considered include:

- Logistic Regression
- Regularised Logistic Regression
- Decision Tree
- Random Forest
- XGBoost
- CatBoost
- FT-Transformer

The final evaluation considers discrimination, calibration and model performance at different recall targets, with particular focus on an 80% recall operating point.

The notebooks numbered `01` to `09` contain the initial reproduction, model development and sensitivity experiments.

The `Final_Pipeline` contains the final controlled modelling workflow. It uses a fixed 60/20/20 training, validation and locked test split. The locked test set is only used after model tuning and threshold selection have been completed.

`Final_Evaluation/Results` contains the results used for the final model comparison, including threshold-independent metrics, calibration analysis, recall/false-positive trade-offs and paired bootstrap comparisons.

## Installation

Install the required Python packages with:

```bash
pip install -r requirements.txt
```

The project was developed primarily using Python and Jupyter notebooks.

## AWS Prototype

`AWS Deployment` contains the source files used for the demonstration deployment of the selected Random Forest model.

The prototype uses AWS Lambda for prediction and a static web frontend hosted using AWS services.

It is intended only as a research demonstration and is not intended for clinical use.

## Dataset

The project uses the Diabetes 130-US Hospitals for Years 1999-2008 dataset associated with the study by Strack et al. (2014).

## Notes

The notebooks contain the main experimental code and displayed outputs. Some intermediate files generated during model development are intentionally not included because they can be regenerated by running the relevant notebooks.
